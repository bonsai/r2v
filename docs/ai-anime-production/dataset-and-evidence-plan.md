# 課題画像・ショット選定と実証データ計画

## 目的

提案システムが何に効くかを判定できるよう、生成前に課題を選び、条件・評価軸・除外条件を固定する。見栄えの良い成功例だけを選ぶことを避ける。

## 選定単位

静止画だけでなく、R2Vの課題に応じて「参照画像セット＋短いショット仕様＋期待する変化／維持すべき属性」を一組として扱う。

## 課題セットの層別

1. **Identity:** 同じキャラクターを保つ。正面・斜め・全身など見え方が異なる参照を含める。
2. **Pose / action:** 立つ、振り向く、驚く、後ずさるなど、観察可能な動作がある。
3. **Composition / camera:** 被写体の位置、画角、距離を指定する。
4. **Style:** 指定した画風を保ち、意図しないスタイル変化を記録する。
5. **Temporal continuity:** フレーム間の形状、衣装、位置、動作の急な変化を評価する。
6. **Multi-reference binding:** 参照画像のどの要素をどのキャラクター／場面に結び付けるかを指定する。
7. **Negative / difficult cases:** 遮蔽、横顔、複数人物、手足が交差する動きなど、失敗が起きやすい課題も含める。

最初のPoCでは全カテゴリを大量に集めず、モデルが扱える短いショットを選び、各カテゴリから少数ずつ含める。

## 課題画像・データの採用基準

- 研究質問のどれを検証するか明確
- 参照画像と期待する結果の条件を文章／YAMLで記述できる
- 解像度、長さ、形式、必要なメタデータが揃う
- 参照要素の正解ラベルまたは人間評価用ルーブリックを作れる
- 出典、ライセンス、利用目的、再配布可否を記録できる
- 個人情報や同意の問題がない、または適切に処理できる
- 成功例だけでなく難例も含む
- 学習用・調整用・最終評価用のデータを分離できる

## データ利用上の注意

- Kaggle上に公開されていることは、任意の商用利用・再配布が許可されていることを意味しない。
- データセットの利用規約、個々の画像・動画のライセンス、人物の肖像・プライバシー、派生物の扱いを確認する。
- 最終評価セットをLoRA学習やパラメータ調整に混ぜない。
- ライセンス不明の素材を本実験の中核データにしない。
- データの出典・取得日・版・ハッシュ・ライセンス判断を記録する。

## 実験レコードの最小スキーマ

各行（JSONL推奨）に最低限以下を記録する。

- `task_id`, `scene_id`, `category`
- `reference_uris`, `reference_license`, `source_url`
- `prompt`, `yaml_spec_version`, `expected_properties`
- `model_id`, `model_version`, `lora_id`, `adapter_id`
- `seed`, `parameters`, `run_id`, `runtime_seconds`, `cost_estimate`
- `output_uri`, `eval_rubric_version`, `jev_verdict`
- `human_scores`, `failure_categories`, `accepted`, `review_notes`

## 評価方法

- 生成条件を比較できるようにし、ベースラインと変更点を明確にする。
- 自動指標だけに頼らず、人間評価を含める。
- 可能なら評価者に条件名を見せず、出力順もランダム化する。
- 評価者間の一致度を記録する。
- 複数回試行し、平均値だけでなくばらつきと失敗例も報告する。
- 結果が悪いショットも除外せず、除外する場合は事前ルールと理由を記録する。

## Kaggle Notebookの実行方針

1. データとライセンスを確認する。
2. 小さなsmoke testで環境・モデル・メモリ・時間を確認する。
3. ベースラインを実行し、ログ形式と出力保存を検証する。
4. 一度に一つの要素を変更するablation notebookを用意する。
5. 実行時間・GPU時間・失敗・メモリ不足を記録する。
6. 評価と集計を別セル／別スクリプトに分け、同じログから再集計できるようにする。
7. 予算・GPU枠・実行時間を考慮して優先順位を付ける。「ぶん回す」は無条件の総当たりではなく、情報量の高い比較を優先する。
