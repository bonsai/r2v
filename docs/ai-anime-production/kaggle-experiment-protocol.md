# Kaggle実験プロトコル：最小構成から検証する

## 原則

最初から全要素を実装しない。研究の初期段階では、比較条件を3つに限定し、原因と結果の対応を説明できる実験を優先する。Kaggleの実行回数ではなく、研究質問に答えられるデータを成果とする。

## 固定するもの

- R2Vベースラインモデルとモデルバージョン
- 課題ショット、参照素材、プロンプトの基本形式
- YAML仕様と実験ログ形式（全条件で共通。初期実験では独立した変数にしない）
- 評価ルーブリックと一次評価指標
- 試行回数、停止基準、コスト計測方法

## 初期の3条件

| 条件 | 構成 | 検証する問い |
|---|---|---|
| A | R2Vベースライン | 基準品質、費用、失敗率はどの程度か |
| B | A + 棒人間／ポーズ制御 | ポーズ制御は動作一致を改善するか。費用に見合うか |
| C | B + JEV型評価・修正ループ | 評価と再生成で初回合格率・採用ショットあたり総費用が改善するか |

## 初期実験に入れないもの

- LoRA学習
- 追加のML制御アダプター
- TPS型品質ゲートの独立比較
- 複数のR2Vモデルを横断する比較
- 多数のパラメータの同時探索

これらは永久に捨てるのではなく、初期結果が示す必要性に応じて次の研究段階で検討する。YAMLは記録基盤として使うが、YAMLそのものの効果を主張するには別実験が必要。

## 主要指標

1. **一次品質指標：** 事前定義した動作／ポーズ一致の人間評価。
2. **副次品質指標：** 指示適合、キャラクター一貫性、重大な破綻の割合。
3. **工程指標：** 初回合格率、再生成回数、レビュー時間。
4. **費用指標：** 生成・再生成・評価・人間レビューを含む採用ショットあたり総費用。

品質と費用の両方を報告する。品質が低い構成の費用が安いだけでは成功としない。評価者には可能な範囲で条件名を隠し、同じルーブリックで比較する。

## 実行手順

1. **Smoke test:** モデル規約、依存関係、GPU／メモリ、推論時間を確認する。
2. **Task freeze:** 課題ショット、参照、プロンプト、採点基準を確定する。
3. **Baseline A:** 失敗を含む全生成結果と費用を保存する。
4. **Pose B:** Aと同じ課題でポーズ制御を追加する。
5. **Eval loop C:** BにJEV型評価と事前定義した修正方針を加える。
6. **Analyze:** 品質差、費用差、ばらつき、失敗分類を集計する。
7. **Decision gate:** 結果に応じて次段階へ進むか、ポーズ制御／評価ループを外すか決める。

## 次段階へ進む条件

- ポーズ制御：動作一致に実用的な改善が見られ、増分コストが許容可能。
- JEVループ：品質を落とさず初回合格率または採用ショットあたり総費用を改善する。
- LoRA／追加アダプター：一貫性など、現在の3条件では解決できない具体的な失敗が観測された場合にのみ検討する。
- TPSゲート：複数工程のレビュー時間・手戻りを測定できる運用環境が整ってから検討する。

## 再現性と停止ルール

- コード、モデルID、データ版、YAML、パラメータ、seed（使用可能な場合）、実行時間、失敗理由、出力URIを記録する。
- タイムアウト、OOM、生成失敗も結果として記録する。
- 結果を見てから課題を都合よく削除しない。
- 試行数不足は「効果なし」ではなく「結論不能」とする。
- GPU時間や学習コストが研究価値に見合わなければ、無理に全実験を実行しない。
