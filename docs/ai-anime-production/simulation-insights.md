# シミュレーションからの気づき：AI映像制作における評価のボトルネック

> 状態：シミュレーション段階の設計仮説。実験結果・実測値ではない。

## 1. 気づきの概要

AI映像制作のボトルネックは、生成速度だけではなく、**AIの評価と人間の評価の不一致**にある可能性がある。

AIが高く評価した画像でも、人間には不自然さや気持ち悪さが残り、採用できないことがある。「惜しい」画像を大量に生成しても、確認・修正・再生成のコストが増えれば、制作全体の効率化にはつながらない。

生成枚数や自動評価スコアだけでなく、人間が実際に採用できる品質を基準にシステムを評価する必要がある。

## 2. 自動化する工程と、人間が判断する工程

### A. AIによる自動検査に向く可能性がある工程

- 背景の物体配置、数、色などの仕様適合性
- 建築物や小道具の位置・形状の整合性
- ショット間で共有される設定の一致
- 指定した画面構成や禁止事項への適合

ただし、背景であっても物語上重要な意味や演出意図がある場合は、人間による確認が必要となる。

### B. 人間との評価一致を検証すべき工程

- 顔や手の不自然さ
- キャラクターの同一性
- 動作のつながり
- 感情表現や演技
- 視覚的な違和感

これらの領域では、AIの評価スコアをそのまま採用判断に使わない。人間の評価との一致度を測定し、自動化できる範囲を段階的に決める。

### C. 人間が主導すべき工程

- 面白さ、感動、演出上の間
- 意図的なデフォルメや違和感
- 作品全体のトーンや表現意図

仕様への適合性だけでは評価しにくい領域であり、機械的な評価によって作品の個性を損なわないようにする。

## 3. 評価方式に関する仮説

評価項目の平均点だけで合否を決める方式には問題がある。背景の整合性が高得点でも、顔や動作に重大な違和感があれば、映像全体として採用できない可能性があるためである。

検証対象として、次の品質ゲートを設計する。

1. 仕様適合性を個別に検査する。
2. 顔、手、動作などの重大な品質欠陥を独立して判定する。
3. 必須条件を満たさない映像は、他項目の高得点で相殺しない。
4. AIと人間の評価が一致しない場合は、人間の確認に回す。
5. 判定の不一致や失敗事例を記録し、評価方式の改善に利用する。

AIと人間の評価一致が十分に検証されていない工程では、無理に自動採用を行わない。

## 4. 検証すべき指標

- **人間とAIの評価一致度**
- **人間が不合格とした映像をAIが合格とする割合**（重大な見逃し）
- 人間が合格とした映像をAIが不合格とする割合
- 初回生成での採用率
- 人間による確認・修正時間
- 再生成回数
- 採用された1ショット当たりの総コスト

全体の一致率が高くても、重大な違和感を見逃すシステムでは、安全に自動化できるとは限らない。人間同士の評価のばらつきも測定し、評価基準自体の再現性を確認する。

## 5. 初期実験の分割

初期段階では、背景ショットとキャラクターショットを分けて検証する。

- **背景ショット：** 仕様適合性の自動検査・修正によって、人間の確認時間を減らせるか。
- **キャラクターショット：** 顔、手、動作、演技について、AIの評価が人間の採用判断とどの程度一致するか。

背景で自動化の有効性が確認されても、その結果をキャラクター表現にそのまま適用できるとは仮定しない。

## 6. 制作サイクルの評価

TPSなどの工程管理方式と、評価結果に応じて次の実験・修正を選択する適応型サイクルを比較する場合、生成速度や生成回数だけを評価指標にしない。

比較の中心は、**人間が採用できる品質の映像を完成させるまでの時間とコスト**とする。サイクルが速くなっても、人間の確認負担や不採用率が増えれば、全体としての効率化とはいえない。

## 7. 現時点での結論

今回のシミュレーションから得られたのは、実験結果ではなく、今後検証すべき設計上の仮説である。

研究の中心課題を、単なる生成速度の向上ではなく、次のように定義する。

**人間の品質基準を損なわずに、どの制作工程までAIに委任できるかを実証する。**

目指すのは、すべての工程を自動化することではない。AIが得意な整合性検査は自動化し、人間の判断が不可欠な表現領域では人間の評価を維持する。その境界を実験によって明らかにし、品質目標を満たす最小構成の制作システムを探る。
