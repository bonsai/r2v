# MRD：アニメ研究論文インサイト・エクスプローラー

- 文書種別：Market Requirements Document
- 状態：Draft
- 対象プロジェクト：bonsai/r2v
- 対象ユーザー：R2V研究者・制作ワークフロー設計者
- 初期コーパス：ユーザーが指定する論文PDF 10本
- 主な実行環境：Kaggle Notebook
- 基本技術：Python、pandas、NumPy、Plotly、RAG

## 1. 背景と課題

研究者は複数の論文PDFを個別に読むだけでは、概念のつながり、研究の偏り、共通する評価指標、矛盾する知見、未検証の研究課題を見つけにくい。一般的なチャット型RAGは質問に回答できても、論文群全体の構造を探索するグラフと、発見を検証可能な根拠に結びつける機能が分離しがちである。

R2Vではアニメ映像の生成・制御・評価を対象に、論文を横断して探索し、根拠付きの問いと仮説を作れる研究環境が必要である。

## 2. ビジョン

**10本の論文PDFを、読むだけの資料群から、根拠をたどりながら質問・探索・発見できる動的な研究知識空間へ変える。**

利用者はキーワードグラフから関連論文・該当チャンクへ移動でき、自然言語で質問して、回答の根拠となる論文・ページ・抜粋を確認できる。

## 3. 目標

1. 10本のPDFを再現可能な方法で取り込み、ページ情報と出典を維持する。
2. 論文・チャンク・キーワード・手法・データセット・評価指標を関連付ける。
3. Plotlyによる動的なグラフで、研究トピックの接続と空白候補を探索できる。
4. RAGで論文群について質問し、回答を原文のページ・チャンクにたどれるようにする。
5. グラフ探索とRAGの回答を連携し、インサイト候補を根拠付きで記録できる。
6. Kaggle上でAPIキー不要の基本フローを再実行できる。

## 4. 非目標

- 初期段階で一般公開された大規模論文検索サービスを作ること
- 10本のPDFだけから研究分野全体の網羅率や統計的に一般化できる結論を主張すること
- 根拠のない自動要約や推測を確定した知見として扱うこと
- 初期MVPで独自の基盤モデルを学習すること
- 有料API、GPU、常時稼働サーバーを必須にすること
- 実写映像の生成研究をR2Vの実験対象に含めること（実写論文が入力された場合は比較資料として分類可能）

## 5. 対象ユーザーと利用シナリオ

### 主要ユーザー
アニメ動画生成の研究・制作工程を調べ、制御・評価・反復改善の研究課題を設計する人。

### 代表シナリオ
- 「この10本では、キャラクター一貫性をどう定義・測定しているか」を質問する。
- グラフ上の「pose control」を選び、関連する論文、評価指標、該当ページを確認する。
- 「自動評価と人間評価が一致しない条件」を論文間で比較する。
- あるキーワードに関係する研究が少ない、または接続が弱い箇所を候補として見つけ、原文を確認する。
- 見つけたインサイト候補を、根拠と反証・限界とともに研究メモへ保存する。

## 6. 価値と成功指標

| 成功領域 | 指標 | MVP目標 |
|---|---|---|
| コーパス完全性 | PDFの取込・識別成功率 | 10本すべてを取込結果とともに記録 |
| 出典追跡 | 回答の根拠から元PDF・ページへ戻れる割合 | 100%を目標 |
| RAG品質 | 回答に付いた引用の有効性 | 評価用質問で人手確認 |
| 探索性 | グラフから論文・チャンクへ移動できるか | 主要ノードで動作 |
| 発見の質 | 根拠付きインサイト候補数 | 初期レビューで5件以上を目安に評価 |
| 再現性 | Kaggleでの再実行 | APIキー不要で基本パイプライン完了 |
| 実用性 | 利用者が関連箇所を見つけるまでの時間 | ベースライン計測後に目標設定 |

数値目標はMVP検証用の暫定値。10本のコーパスから分野全体に一般化できる比率や結論は主張しない。

## 7. 原則

- PDFは出典の正本。抽出テキストやチャンクは派生データとして扱う。
- RAGの回答には、論文ID・ページ番号・引用抜粋を付ける。
- 回答できる根拠がない場合は「このコーパスからは確認できない」と返す。
- 共起、意味的類似、引用、同じデータセットの使用などを異なる関係として表現する。
- 可視化上の近さを、因果関係や学術的な重要度と混同しない。
- インサイトは「候補」として提示し、原文確認・反証探索を経て採用する。
- PDF・抽出テキストの保存・公開はライセンスと著作権条件を確認する。非公開のPDFや全文抽出物をGitへ無条件にコミットしない。
- アニメ研究を中心に分類し、実写／2Dアニメ／3Dアニメ・CG／混在／不明を区別する。

## 8. MVPの境界

初期版は10本の指定PDF、ローカルファイル入力、ページ対応テキスト抽出、チャンク索引、キーワードグラフ、引用付き質問応答、Kaggleノートブックに限定する。埋め込みモデルによる意味検索、外部コーパス拡張、共同編集、ログイン、常時公開アプリはMVP後に判断する。

## 9. リスク

- PDFの二段組、数式、図表、OCRにより抽出テキストが壊れる。
- チャンク境界が論文の主張や条件を切り離す。
- グラフのクラスタが抽出方式や頻出語の影響を受ける。
- RAGが根拠を誤って結び付けたり、論文にない主張を生成する。
- 10本という小規模コーパスでは、見つからないことが研究分野に存在しないことを意味しない。
- Kaggleのネットワーク・セッション・ストレージ制約に影響される。

## 10. MVP後の判断

MVPの利用記録と評価質問を使って、意味検索、引用・参考文献グラフ、原文と要約の並列表示、インサイト比較、追加PDFの取り込みを優先順位付けする。
