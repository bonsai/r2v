# nwman — LAN-only production network

目的：生成AIアニメ制作の素材・生成ワーカー・JEV評価・メタデータをLAN内で接続する。Kubernetes移行を見越して境界を整理するが、初期PoCでKubernetesを必須にしない。

## 設計原則

- 初期構成は単一LAN内。公開インターネットに管理画面・API・ストレージを露出しない。
- 外部ネットワークへの通信は既定拒否。必要なモデル／データ取得だけを管理端末の明示的な取得ジョブとして許可し、チェックサム・ライセンス・出典を記録する。
- 人間の制作端末、管理／制御面、生成ワーカー、評価ワーカー、データ面を論理分離する。
- 生成ワーカーはジョブを受け取り、成果物とログを返す。共有ストレージとDBを直接変更できる範囲を絞る。
- K8sを見越して、各サービスはAPI／キュー越しに疎結合にし、状態をコンテナのローカルディスクだけに置かない。
- LAN内でも認証、最小権限、バックアップ、監査ログを前提とする。

## 論理コンポーネント

1. **Studio LAN** — 制作端末、レビューUI、管理端末。
2. **Control plane** — 内部DNS、ジョブAPI／キュー、認証、設定、監視。
3. **Worker plane** — R2V生成、画像処理、JEV評価。GPUの有無やモデル依存でワーカーを分ける。
4. **Data plane** — 原本参照、生成候補、採用素材、実験ログ、RAG/SQLite。原本・候補・採用物は別の名前空間／権限で扱う。
5. **Kubernetes-ready boundary** — API、キュー、オブジェクトストレージ、永続DB、ワーカーを独立させ、後でDeployment / Job / Service / PVCへ対応づける。

## セキュリティ境界

- ルーター／ファイアウォールでLAN外からの着信を拒否する。
- 管理画面は管理端末または管理VLANからのみ到達可能にする。
- モデルやデータセットの取得は専用のegress gateway経由に限定し、通常の生成ワーカーにはインターネットアクセスを与えない。
- 秘密情報をYAMLやGitに保存しない。認証情報は環境変数・Secret管理へ。
- Kubernetes導入後もNetworkPolicy、RBAC、Pod Security、Secret管理を有効にする。
